# Precision Study · Design research and code audit

This record maps public design evidence to the current Drill/EI implementation. It does not treat product screenshots or public SDKs as access to private product UI code.

## Evidence and limits

- [Linear's March 2026 refresh](https://linear.app/now/behind-the-latest-design-refresh) describes quieter navigation, consistent headers, fewer decorative icons, and softer separators. [Linear's filter documentation](https://linear.app/docs/filters) and [mobile navigation update](https://linear.app/changelog/2026-01-22-customize-your-navigation-in-linear-mobile) provide interaction context. The public [`linear/linear` repository](https://github.com/linear/linear) contains SDK/import/codegen tools, not the product frontend.
- [Geist colors](https://vercel.com/geist/colors), [materials](https://vercel.com/geist/materials), [typography](https://vercel.com/geist/typography), [menus](https://vercel.com/geist/menu), and [Vercel's web interface guidelines](https://vercel.com/design/guidelines) describe the current public design rules. The public [Vercel Examples UI package](https://github.com/vercel/examples/tree/main/internal/packages/ui/src) is older sample code and is not the current Dashboard source. No product component code was copied.
- Existing `frontend/drill/src/styles.css` already defines usable dark/light semantic colors, spacing, radii, and focus tokens. A global recolor would add risk without addressing the measured problems.

## Design baseline

- Dark: existing `#101216` app, `#181b20` surface, `#20242b` elevated, `#2b3038` border. Light equivalents remain in `[data-color-scheme="light"]`. Accent identifies interaction; mastered, review, danger retain semantic colors.
- Page titles 22–28px, section titles 16–18px, body 14–16px, secondary copy 12–13px, metric values 24–36px. Practice index and mobile form controls were the main outliers; full-screen question controls are intentionally independent.
- Spacing uses existing 4/8/12/16/24/32px tokens where shared. The type filter and diagnosis metrics use one separator per relationship. Buttons and inputs remain at least 44px high on mobile where changed.
- The existing dense heatmap matrix, attempt-by-attempt history, URL-backed filters, Drill/EI target semantics, and ECharts resize lifecycle are preserved.

## Visual QA scope

The built Vue app was rendered through a read-only synthetic API in Chromium at 375, 390, 430, 820 and 1180px for Drill/EI Practice, History, Progress, Diagnostics, and the Drill selected heatmap. No tested page had document overflow; the Progress ECharts canvas resized from 788px to 900px and back to 788px after portrait/landscape/portrait changes. A real theme-button click switched the Progress page to its light tokens. Static representative fixtures additionally cover 1440px and QuestionView at iPad landscape width. The synthetic data and Chromium checks cannot establish behavior for every live response or Safari PWA shell. The complete frontend test/build results and remaining device checks are reported with the delivery.
